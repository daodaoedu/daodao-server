# DaoDao Server - 業務邏輯流程文件

## 主要業務流程

### 1. 用戶註冊與認證流程

#### Google OAuth 認證流程
```
用戶點擊 Google 登入
↓
重定向至 Google OAuth
↓
Google 返回用戶資料
↓
檢查是否為已註冊用戶
├─ 是 → 返回正式用戶資料 + JWT Token
└─ 否 → 建立臨時用戶記錄 + Session
```

**涉及服務**:
- `oauth.service.ts:85-124` - Google 策略處理
- `auth.service.ts` - 用戶查詢與臨時用戶建立

#### 用戶註冊流程
```
臨時用戶填寫完整資料
↓
驗證資料完整性 (姓名、聯絡方式等)
↓
檢查用戶名稱是否重複
↓
資料庫交易開始
├─ 建立基本資訊記錄
├─ 建立聯絡方式記錄  
├─ 建立正式用戶記錄
├─ 建立職位關聯
└─ 發送驗證郵件
↓
刪除臨時用戶記錄
↓
返回正式用戶 + 新 JWT Token
```

**涉及服務**:
- `user.service.ts:350-505` - 用戶註冊主流程
- `email.service.ts` - 驗證郵件發送

### 2. 專案管理流程

#### 專案建立流程
```
用戶提交專案資料
↓
角色權限檢查
├─ 角色2 → 拒絕 (無權限)
├─ 角色3 → 檢查專案數量 (限制3個)
└─ 其他角色 → 允許
↓
資料驗證 (必填欄位、日期邏輯)
↓
資料庫交易開始
├─ 建立專案記錄
├─ 建立里程碑記錄 (如有)
└─ 建立任務記錄 (如有)
↓
返回完整專案資料
```

**涉及服務**:
- `project.service.ts:137-274` - 專案建立主流程

#### 專案查詢流程
```
請求專案列表/詳情
↓
權限檢查
├─ 無登入 → 僅公開專案
├─ 專案擁有者 → 所有自己的專案
└─ 其他用戶 → 僅公開專案
↓
應用篩選條件 (狀態、搜尋等)
↓
查詢資料庫 (包含關聯資料)
↓
格式化回應資料
```

**涉及服務**:
- `project.service.ts:278-342` - 專案詳情查詢
- `project.service.ts:346-444` - 專案列表查詢

### 3. 資源管理流程

#### 資源建立流程
```
用戶提交資源資料
↓
資料驗證 (Zod Schema)
↓
驗證分類是否存在
↓
資料庫交易開始
├─ 轉換資料格式 (API → DB)
├─ 建立資源記錄
└─ 建立標籤關聯
↓
返回完整資源資料
```

**涉及服務**:
- `resource.service.ts:396-448` - 資源建立流程
- `transform.service.ts` - 資料格式轉換
- `tag.service.ts:99-131` - 標籤關聯處理

#### 資源查詢流程 (含複雜篩選)
```
請求資源列表
↓
標籤篩選預處理
├─ 有標籤篩選 → 先查詢標籤關聯的資源ID
└─ 無標籤篩選 → 跳過
↓
建構查詢條件
├─ 類型、費用、難度篩選
├─ 分類篩選
├─ 搜尋關鍵字 (名稱、描述)
└─ 標籤篩選結果
↓
執行分頁查詢 (cursor-based)
↓
批量查詢資源標籤
↓
組裝完整資源資料
```

**涉及服務**:
- `resource.service.ts:169-388` - 資源查詢主流程
- `resource.service.ts:50-161` - 資源詳情查詢

### 4. 標籤系統流程

#### 標籤建立與關聯流程
```
為實體設置標籤 (資源、想法等)
↓
刪除舊的標籤關聯
↓
處理新標籤列表
├─ 檢查標籤是否存在
├─ 不存在 → 建立新標籤
└─ 存在 → 使用現有標籤
↓
建立實體-標籤關聯記錄
```

**涉及服務**:
- `tag.service.ts:99-131` - 實體標籤設置
- `tag.service.ts:15-34` - 標籤建立

#### 標籤統計與清理流程
```
定期清理未使用標籤
↓
查詢沒有關聯的標籤
↓
批量刪除未使用標籤
```

**涉及服務**:
- `tag.service.ts:262-286` - 未使用標籤清理

```
users (正式用戶)
├── contacts (聯絡方式)
├── basic_info (基本資訊)
├── location (地區資訊)
├── roles (角色)
└── user_positions (職位關聯)
    └── position (職位)

temp_users (臨時用戶)
├── google_id
├── email
├── name
└── photo_url

project (專案)
├── users (創建者)
├── milestone (里程碑)
│   └── task (任務)
└── 權限控制欄位

resources (資源)
├── users (創建者)
├── categories (主分類)
├── categories (子分類)
├── entity_tags (標籤關聯)
│   └── tags (標籤)
└── resource_review (評價)

├── entity_type (實體類型)
```

```
未認證用戶
↓ Google OAuth

↓ 完成註冊
正式用戶 (JWT 驗證)
```

## 關鍵業務規則

### 用戶管理
1. **角色權限**:
   - 角色2: 無法建立專案
   - 角色3: 最多3個專案
   - 其他角色: 無限制

2. **完整度評分**:
   - 自我介紹: 基礎2分 + 長度加分
   - 分享內容: 基礎2分 + 長度加分
   - 標籤: 每個0.5分，最多4分
   - 聯絡方式: 1分
   - 地區: 1分
   - 職位: 1分

### 專案管理
1. **權限控制**:
   - 公開專案: 所有人可查看
   - 私人專案: 僅創建者可查看
   - 修改/刪除: 僅創建者可操作

### 資源管理
1. **權限控制**:
   - 查看: 所有人 (已發布資源)
   - 修改/刪除: 僅創建者
   - 軟刪除: 標記 deleted_at

### 標籤系統
1. **自動管理**:
   - 避免重複標籤建立
   - 自動清理未使用標籤
   - 支援多實體類型關聯

## 效能考量

### 查詢最佳化
1. **用戶查詢**: 先查詢再計算完整度，避免資料庫計算
2. **資源查詢**: 標籤篩選預處理，減少複雜查詢
3. **分頁機制**: 使用 cursor-based 分頁，效能較佳

### 資料庫設計
1. **軟刪除**: 保留資料完整性
2. **關聯查詢**: 使用 include 減少 N+1 查詢
3. **交易支援**: 確保資料一致性
