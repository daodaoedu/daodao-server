# Project Features Comparison: TypeScript vs JavaScript Implementation

## 概述

本文檔分析比較了 DaoDao 專案中 TypeScript（`src/` 目錄）和 JavaScript（根目錄）兩個版本的專案功能實現差異。

## 架構差異

### TypeScript 版本 (src/)
- **現代化架構**: 使用 Prisma ORM
- **類型安全**: 完整的 TypeScript 類型定義
- **分層架構**: Controller → Service → Database
- **標準化響應**: 統一的 API 回應格式
- **中間件系統**: 完整的驗證和權限管理

### JavaScript 版本 (根目錄)
- **傳統架構**: 使用 Sequelize ORM
- **直接資料庫操作**: 控制器直接操作模型
- **版本控制機制**: 支援專案版本管理
- **交易處理**: 複雜的資料庫交易邏輯

## 功能對比

### 1. 專案創建 (Create Project)

#### TypeScript 版本特點:
- **檔案**: `src/controllers/project.controller.ts:20-51`
- **服務層**: `src/services/project.service.ts:135-271`
- 使用 Prisma 事務處理
- 完整的類型驗證和錯誤處理
- 支援里程碑和任務一次性創建
- 統一的服務回應格式

#### JavaScript 版本特點:
- **檔案**: `controllers/project.js:63-212`
- 複雜的角色驗證邏輯
- 手動 SQL 事務管理
- 支援馬拉松關聯
- 包含專案數量限制檢查

### 2. 專案查詢 (Get Projects)

#### TypeScript 版本:
- **檔案**: `src/controllers/project.controller.ts:87-122`
- **服務**: `src/services/project.service.ts:344-441`
- 統一的查詢參數處理
- 支援排序、搜尋、分頁
- 權限控制整合
- 標準化的查詢結果

#### JavaScript 版本:
- **檔案**: `controllers/project.js:215-473`
- 多個查詢端點：
  - `getFilteredProjects`: 複雜的權限邏輯
  - `getPublicProjects`: 僅公開專案
  - `getProjects`: 所有專案（管理員用）
  - `getMyProjects`: 個人專案（版本控制）

### 3. 專案更新 (Update Project)

#### TypeScript 版本:
- **檔案**: `src/controllers/project.controller.ts:128-161`
- **服務**: `src/services/project.service.ts:446-494`
- 簡化的更新邏輯
- 類型安全的資料處理
- 直接更新模式

#### JavaScript 版本:
- **檔案**: `controllers/project.js:617-822`
- **版本控制機制**: 當狀態從 "Not Started" 變更時自動創建版本 2
- 複製里程碑和任務到新版本
- 複雜的條件更新邏輯

### 4. 路由配置

#### TypeScript 版本:
- **檔案**: `src/routes/project.routes.ts`
- 完整的中間件整合
- 統一的驗證架構
- RESTful API 設計
- 支援專案複製功能

#### JavaScript 版本:
- **檔案**: `routes/project.js`, `routes/projectList.js`
- 簡單的路由定義
- 包含額外的子資源路由（里程碑、任務、筆記、成果、評論）
- 分離的專案列表路由

## 核心差異分析

### 1. 資料庫操作
- **TypeScript**: Prisma ORM，類型安全，現代化 API
- **JavaScript**: Sequelize ORM，傳統 SQL 操作，手動事務管理

### 2. 版本控制
- **TypeScript**: 無版本控制機制
- **JavaScript**: 複雜的版本控制系統，支援專案版本演進

### 3. 錯誤處理
- **TypeScript**: 統一的服務層錯誤處理，標準化回應格式
- **JavaScript**: 分散的錯誤處理，直接回應錯誤

### 4. 類型安全
- **TypeScript**: 完整的類型定義，編譯時錯誤檢查
- **JavaScript**: 無類型檢查，運行時錯誤風險

### 5. 功能完整性
- **TypeScript**: 基礎 CRUD 功能，專案統計，專案複製
- **JavaScript**: 完整的專案生命週期管理，包含子資源操作

## 建議

### 短期改進
1. **合併版本控制邏輯**: 將 JavaScript 版本的版本控制機制移植到 TypeScript 版本
2. **增強子資源支援**: 在 TypeScript 版本中添加里程碑、任務等子資源操作
3. **統一響應格式**: 確保兩個版本使用相同的 API 響應格式

### 長期規劃
1. **完整遷移**: 逐步將 JavaScript 版本的功能完全遷移到 TypeScript 版本
2. **保持單一實現**: 避免維護兩套重複的功能實現
3. **測試覆蓋**: 確保遷移過程中功能的完整性和正確性

## JavaScript 版本獨有邏輯清單

### 1. 專案版本控制系統
- **位置**: `controllers/project.js:694-786`
- **邏輯**: 當專案狀態從 "Not Started" 變更時，自動創建版本 2
- **功能**: 
  - 保留原始版本作為設計藍圖
  - 複製所有里程碑和任務到新版本
  - 維護專案歷史記錄

### 2. 角色驗證與限制
- **位置**: `controllers/project.js:104-125`
- **邏輯**:
  - 角色 ID = 2: 完全禁止創建專案
  - 角色 ID = 3: 限制最多 3 個專案
- **驗證**: 基於 `user.roleId` 進行角色檢查

### 3. 用戶查詢邏輯
- **位置**: `controllers/project.js:91-94`
- **邏輯**: 使用 `external_id` 而非 `id` 查詢用戶
- **特殊處理**: `req.user._id` 對應資料庫的 `external_id`

### 4. 馬拉松關聯功能
- **位置**: 多處使用 `ProjectMarathon` 模型
- **功能**: 專案可與馬拉松事件關聯
- **資料格式**: 包含馬拉松的開始/結束日期

### 5. 複雜權限邏輯
- **位置**: `controllers/project.js:225-272`
- **功能**: `getFilteredProjects` 的多層權限控制
- **邏輯**: 組合公開專案與個人私有專案的查詢

### 6. 版本查詢機制
- **位置**: `controllers/project.js:476-544`
- **功能**: `getMyProjects` 只返回每個專案的最新版本
- **邏輯**: 群組查詢最大版本號

### 7. 刪除邏輯
- **位置**: `controllers/project.js:825-871`
- **功能**: 刪除所有相同 `external_id` 的版本
- **保護**: 檢查第一個版本的擁有權

## 風險評估

### 高風險項目
- **專案版本控制**: 複雜的資料遷移和邏輯轉換
- **權限系統**: 可能影響現有用戶權限
- **資料一致性**: 多版本資料的一致性維護

### 緩解措施
- 階段性實施，每個階段完整測試
- 保持向後兼容性
- 實施資料備份和回滾機制

## 結論

TypeScript 版本提供了更現代化、類型安全的實現，但在功能完整性方面不如 JavaScript 版本。JavaScript 版本包含複雜的業務邏輯和版本控制機制，但缺乏類型安全保障。建議採用漸進式遷移策略，按照上述任務清單逐步將 JavaScript 版本的核心業務邏輯遷移到 TypeScript 版本中。
