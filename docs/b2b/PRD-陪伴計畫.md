# PRD｜DaoDao 陪伴計畫（老師 / 社群經營者後台）

## 產品定位

> 「陪伴計畫不是課程，是一段『我陪你走一段時間，一起完成某件事』的關係。」

DaoDao 做的不是典型課程（非國考、非學科考試），而是技能養成 / 自我成長 / 創作類的**非典型學習**。這類學習最大的挑戰不是「教得好不好」，而是：**課程/陪伴結束後，學員會不會真的持續**。

陪伴計畫後台的價值，不是幫老師「管理班級績效」，而是幫老師「看見陪伴的歷程，知道什麼時候該回應、該關心誰」。

---

## 這不是補習班邏輯

| 補習班模式（不適用） | 陪伴計畫（適用） |
|----------------------|-------------------|
| 標準化進度 | 每個人路徑不同 |
| 對／錯、分數 | 沒有標準答案 |
| 完課率、留存率報表 | 持續力、關係的溫度 |
| 招生 / 續班是目的 | 持續探索、被陪伴本身是目的 |
| 老師 = 教學權威 | 老師 = 陪伴者 / 看見者 |

---

## 目標用戶

| 角色 | 描述 |
|------|------|
| 老師 | 帶一群學員長期陪伴式學習/創作 |
| 社群經營者 | 經營一個持續性的成長社群，不一定教課 |

與「共同挑戰」的差異：**共同挑戰是任何人都能發起的短期／季度性活動**；**陪伴計畫是老師/社群經營者長期、關係導向的經營場域**。

---

## 核心概念

```
陪伴計畫（Companion Program）
  由老師/社群經營者建立
  邀請或開放學員/夥伴加入
  沒有強制任務拆解，重點是「持續同行」

  底層沿用：
    practice（每位夥伴自己的打卡/實踐目標）
    practice_checkins（打卡紀錄）

  老師的角色：
    看見（誰在動、誰卡住）
    回應（留言、鼓勵、關心）
    不是指派任務、不是打分數
```

---

## Phase 1 範圍：輕量陪伴

聚焦在「看見與回應」，不做任務/里程碑拆解（那是 Phase 2 的「結構陪伴」）。

### 老師可以做的事
- 建立陪伴計畫（名稱、說明、公開或封閉）
- 邀請夥伴加入 / 開放自由加入
- 看動態牆：所有夥伴的打卡與歷程，即時更新
- 對打卡留言、按讚、給予回饋
- 看「可能需要關心」名單：一段時間沒有動靜的夥伴（非催促、是提醒老師去關心）
- 看「值得被看見」名單：持續力特別強、或歷程特別有感染力的夥伴，可邀請對方公開分享
- 匯出/整理值得記錄的故事（未來可用於社群分享，非招生報表）

### 夥伴（學員）可以做的事
- 加入陪伴計畫
- 打卡、記錄歷程（沿用既有 practice 打卡機制）
- 收到老師的留言與鼓勵
- 看到自己的持續記錄（連續天數、加入以來的歷程）

### Phase 1 不做
- 任務拆解、里程碑、進度百分比（Phase 2：結構陪伴，才會用到 project + task + milestone）
- 排名榜、競爭機制（陪伴計畫的調性不適合比較）
- 完課率 / 留存率報表（不是這個功能的目的）
- 付費機制

---

## Phase 2 範圍：結構陪伴

當老師需要陪伴一個「有階段性目標」的歷程時（例如陪學員完成一本書、一個作品），才疊加：

- `project` 作為陪伴計畫的載體
- `task` 拆解階段性任務
- `milestone` 記錄關鍵進展
- `outcome` 記錄最終成果

Phase 1 的 practice 打卡不會被取代，兩者可並存：陪伴計畫底下，有人打日常卡、也有人在推進一個階段性任務。

## 產品調性原則

在設計任何功能前先自問：

```
這個功能是在「幫老師管理績效」，還是「幫老師陪伴」？
                    ↓
      如果是前者 → 停下來，重新設計
```

具體守則：
- 不用「完課率」「留存率」這類管理語言，改用「持續力」「陪伴歷程」
- 不做排名比較，改用「被看見」「被回應」
- 停滯提醒的語氣是「關心」，不是「警訊」或「業績提醒」
- 老師後台的第一畫面永遠是「動態與關係」，不是「數據儀表板」

---

## 成功指標

指標本身也要符合陪伴調性，避免落入管理指標的陷阱：

| 指標 | 說明 |
|------|------|
| 平均陪伴時長 | 夥伴持續留在計畫中的天數（不是完課率） |
| 回應率 | 老師對夥伴打卡的留言/互動比例（陪伴的溫度） |
| 課後/活動後持續率 | 主題性活動結束後，仍持續打卡的比例 |
| 夥伴自發分享率 | 願意公開自己歷程的比例（信任與認同的訊號） |

## 與共同挑戰的關係

```
共同挑戰                          陪伴計畫
════════════                      ════════════════════
任何人都可發起                    老師 / 社群經營者發起
Season 制，有時效性                跟著關係走，無強制期限
排名榜、社群競爭感 OK              不比較，重點是關懷
底層：practice + checkins         底層：practice + checkins（Phase 1）
                                   + project/task/milestone（Phase 2）

兩者共用同一套打卡引擎，
差別在「發起人、調性、UI 語言」，不是底層技術。
```
